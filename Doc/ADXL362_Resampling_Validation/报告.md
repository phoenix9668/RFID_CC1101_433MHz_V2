# ADXL362 方案二：实现与历史数据回放验证

日期：2026-09-22。状态：软件候选版已实现并构建，未烧写板卡，未完成量产验收。

## 结论

方案二已接入 V3.8 隔离开发分支：ADXL362 选择 50 Hz 档位，根据 RTC 和有效 FIFO 数据量重建采样时间，再通过固定内存的抗混叠滤波重采样，给原行为算法提供连续 25 Hz 输入。原分类器及阈值、191 字节报文、EEPROM 布局和 20 分钟 RTC 上报窗口均未修改。

在这批历史数据上，以约 39.5 Hz 的**模拟输入**进行回放，共有 **5,934 个名义秒**可比较，新旧算法有 **557 秒分类不同，一致率 90.61%**。该数字不是识别准确率，也不是真实 50 Hz 上板测试结果。

增加“25 Hz 原数据只经过同一滤波器”的控制组后，它与原算法有 555 秒不同，而完整方案二与该控制组仅有 52 秒不同。这支持“本次对照差异主要来自新增滤波”的解释，不能据此认定变化后的分类更正确。

按用户最新指定的逐类门槛，**采食在合并数据上达到 90%；活动在仅 11 秒的有限样本上达到 95%；爬跨、反刍缺乏样本，仍无法验收**。不再要求总体分类一致率达到 100%。另有单文件采食略低于门槛，详见下节，不能把合计达标解释为每条记录都达标。

## 更新后的逐类验收标准

门槛为：爬跨、活动各不低于 95%；采食、反刍各不低于 90%。类别 3 的原名称为“运动”，这里与用户所说“活动”对应。静止、其他不设本轮通过门槛。

当前没有人工标注，因此先将门槛解释为**相对原算法的逐秒一致性**，不是实际识别准确率。为同时约束漏判和误判，保守要求以下两项都达到门槛：

- 对照召回率 = 新旧算法同一秒均判为该类的秒数 / 原算法判为该类的秒数。
- 对照精确率 = 新旧算法同一秒均判为该类的秒数 / 方案二判为该类的秒数。
- 不使用“该类与非该类全部秒数的准确率”，避免稀有类完全漏判仍获得接近 100% 的误导结果；也不以类别总数接近代替逐秒一致。
- 分母为零则该项不可评估，不按 100% 或通过处理。阈值使用未四舍五入的数值判断。

以下为约 39.5 Hz 模拟输入，跨文件合并可比秒数后的结果：

| 行为 | 门槛，两项均需满足 | 原算法秒数 | 方案二秒数 | 同秒同类 | 对照召回率 | 对照精确率 | 当前结论 |
|---|---:|---:|---:|---:|---:|---:|---|
| 爬跨 | 95% | 0 | 0 | 0 | 不可评估 | 不可评估 | 无法验收 |
| 活动 | 95% | 11 | 11 | 11 | 100.00% | 100.00% | 样本内达标，覆盖很少 |
| 采食 | 90% | 3,155 | 3,124 | 2,933 | 92.96% | 93.89% | 合并数据达标 |
| 反刍 | 90% | 0 | 0 | 0 | 不可评估 | 不可评估 | 无法验收 |

其他模拟速率下，活动也均为 11/11 秒一致；采食结果如下。不同速率重复使用同一批原始数据，不能累加为独立验证样本。

| 模拟输入速率 | 采食对照召回率 | 采食对照精确率 | 合并数据门槛 |
|---|---:|---:|---|
| 39.502107 Hz | 92.96% | 93.89% | 达到 90% |
| 50 Hz | 92.74% | 93.87% | 达到 90% |
| 57.5 Hz | 92.74% | 93.81% | 达到 90% |

**逐文件例外：**`vofa_9.15.11.xlsx` 在约 39.5 Hz 模拟组中的采食对照召回率为 **698/777 = 89.83%**，精确率为 **698/774 = 90.18%**；50 Hz 组召回率为 **699/777 = 89.96%**。两组均未满足“该文件两项各达到 90%”。因此目前只能称合并数据的采食指标达标，不能称所有记录均已达标。

11 秒活动可能属于相关的连续片段，不等同于 11 次独立活动事件，更不足以保证现场活动识别达到 95%。爬跨和反刍应补充覆盖数据；没有标注时，也不能判断原算法是否已经漏掉这些行为。本次未通过调整滤波器或分类阈值来追求对照分数。

### 可复现验收

新增 `Tools/behavior_acceptance.py` 自动重建 28 份逐秒 CSV 的转换矩阵，与原汇总核对，再输出 [acceptance.json](acceptance.json)。文件记录各速率合并结果、逐记录结果、分母与命中数、明确的通过/不通过/不可评估状态，以及输入和工具 SHA-256。后续完整回放会自动调用同一工具。

```text
python Tools/behavior_acceptance.py --results <结果目录>/results.json
python -B Tests/test_behavior_acceptance.py
```

只需标准 Python 库，不重新生成模拟数据，不修改 Excel。加 `--require-pass` 可用于验收门禁：任一非控制组合并结果不通过或缺乏类别覆盖时，脚本返回退出码 2。本批结果因爬跨、反刍无覆盖，门禁不会放行。6 项专项测试已通过，覆盖空类别、恰好达到门槛、漏判、误判、四舍五入边界和非法矩阵。

## 数据范围与限制

- 共读取 4 个 Excel、5 个工作表，合计 **150,526 组三轴样本**。原文件只读，读取前后 SHA-256 一致。
- 用户确认采集时设置 25 Hz，但没有历史实际 ODR 测量。本报告按 25 Hz 建立名义时间轴，不将其当作经独立时钟确认的真实时间。
- 使用原始 X/Y/Z 列，不使用 X1/Y1/Z1 派生差值；不把 T 列解释为采样时间。
- `example_data.xlsx` 的 Sheet2 存在两次样本序号重置，保守拆为三段各 31 个样本，不跨段拼接。这些片段太短，不能用于有效行为一致率统计。
- 不同文件的量程、单位换算和佩戴方向未独立确认。分析保留原始整数值，不擅自缩放数据或修改阈值。
- 所有 39.5/50/57.5 Hz 输入都由历史 25 Hz 数据通过 SciPy 重建。这只能验证处理链路，不能产生原始记录中不存在的运动信息，也无法完整模拟传感器切换 ODR 后的模拟滤波变化。
- 没有人工标注。基线分类只是对照，不是真值；本批可比区间内原算法的爬跨、反刍输出均为零，这两类尚未得到有效覆盖。

## 实现要点

- 生产候选配置为 `FILTER_CTL=0x52`，4 g / 50 Hz / HALF_BW。此前定位内部时钟问题的诊断程序仍保留 25 Hz 基线。
- 每批次之间以 RTC 时间与实际读出的 FIFO words 重建均匀时间轴；这不是对每个样本单独打硬件时间戳，需要后续上板检查唤醒和服务延迟。
- 初始时间校准会丢弃首批数据；发生溢出、传输失败或不连续输入时重新预热，不把缺失数据伪造成正常行为。
- FIR 使用 8 Hz 截止、Kaiser beta=5、正负 320 ms 支撑的候选设计。这里的截止按 SciPy `firwin` 定义为约 -6 dB 点，不等同于原模拟滤波器的 -3 dB 带宽。MCU 只做整数运算，固定 48 项环形缓冲，没有动态分配。[FIR 定义](https://docs.scipy.org/doc/scipy/reference/generated/scipy.signal.firwin.html)
- 滤波带来约 320 ms 的信号延迟。生产统计继续按算法结果可输出的时间记账，不回填已经封存的 20 分钟窗口；原分类器原有历史修正延迟也仍保留。
- FIFO 水位仍为 450 words。约 39.5 Hz 时约 3.8 秒到水位，不能沿用固定等 6 秒再读取。另有基于观察速率的兜底读取期限，测试覆盖了丢失 FIFO 中断的情况。
- 活动/静止检测寄存器字节保持原值，其物理时间随 ODR 改变；它们不驱动当前主程序的 FIFO 分类链路。

## 软件检查

**12 项主机测试通过**，包含不变分类器与指定基座的逐输出回归、50 Hz 配置、25 Hz 诊断兼容、滤波直流与符号边界、通带和混叠抑制、断流、RTC 回绕，以及原有协议、驱动、存储和复位测试。

39.502 Hz、50 Hz、65 Hz、丢失 FIFO IRQ 四种场景分别完成了 **4 小时 20 分钟软件仿真**。首窗口明确允许校准预热损失，随后 12 个完整窗口各输出 1,200 次分类。这里不是板卡真实运行时长。

三种构建均成功，未出现编译器警告。链接器继续预留 2 KiB 栈。Debug 编译器静态栈估计中，新增 `resampler_push` 为 80 B、`sample_clock_batch` 为 32 B；这不是整条调用链或上板栈高水位测量。

## 验收边界

目前可以确认：代码可构建、重采样按 40 ms 时间网格输出、软件时序与协议回归通过，并已量化历史数据上的分类变化。

目前不能确认：真实 50 Hz 采集下的分类准确率、所有六类行为表现、具体续航代价，以及现有板卡 STOP 唤醒时的时间重建误差。

下一步应采集真实 50 Hz 档位数据并同时保留 RTC/逻辑分析仪时间证据，检查 FIFO、输出节奏和 20 分钟边界，再测生产功耗。滤波参数是候选值，不能为了提高无标注数据的一致率而把原算法输出当作正确答案去拟合。

本轮没有烧写、复位或访问板卡，也没有修改原始 Excel。
